# Experiment record

Conducted November 15, 2026. Extracted as a standalone portfolio experiment November 25, 2026. The implementation, protocols and measurements come from the original work; packaging does not constitute a new GPU run.

## Iterations

1. **Profile the native runtime.** Sweep prefill and decode at three context lengths, keeping ordinary timings separate from Nsight instrumentation. Identify redundant relative-bias conversion passes in the safe B300 attention fallback.
2. **Reject an earlier routing adaptation.** A TokenSpeed-derived routing/quantization candidate was slower in all 24 eligible operation-level cases (14.3–96.6% more latency). This did not measure the performance of TokenSpeed's complete serving engine. Its sanitized results are retained in `results/tokenspeed-experiment.json`; its implementation and third-party dependency tree are outside this extraction.
3. **Fuse the relative-bias helper.** Combine indexing, gather, validity masking and `nan_to_num` behavior in one Triton kernel, preserving finite bit patterns, signed zero, and special-value semantics.
4. **Evaluate the candidate.** Exactness checks passed and prefill improved. Reject adoption under the unchanged decode gate; CUDA-graph serving validation was not reached.

## Measurements

| Context | Native prefill (ms) | Fused prefill (ms) | Native decode (ms) | Fused decode (ms) |
| ---: | ---: | ---: | ---: | ---: |
| 256 | 46.382 | 34.067 | 41.947 | 42.353 |
| 1,024 | 54.275 | 43.622 | 43.008 | 42.540 |
| 4,096 | 135.968 | 105.877 | 42.266 | 42.263 |

The primary 4,096-token prefill speedup has a paired 95% bootstrap interval of approximately 1.283–1.285×. Both confirmation blocks improve. At 256 tokens, mean decode latency rises by 0.406 ms (0.97%). The helper is not called during these decode cases and the interval spans parity, so this observation does not establish a causal regression. It still fails the predeclared gate.

Separate Nsight attribution records 48 helper calls per prefill: 1,776 native kernels versus 48 fused kernels per forward. At 4,096 tokens, helper GPU kernel unions fall from approximately 35.3 to 6.77 ms per GPU. Rank times are not summed.

The timing boundary is the complete eager forward: embedding, layers, cache writes, final norm and last-token head. It excludes HTTP, scheduling, sampling, startup, compilation and state restoration. Each observation uses the maximum synchronized rank-local wall time. Synthetic inputs, batch size one and concurrency one limit generalization; 4,096 is not a maximum-context claim.

## Running the extracted code

From the repository root:

```bash
# CPU protocol, analysis, trace-attribution and scalar correctness checks
uv run --no-project python -m unittest discover -s tests

# Inspect the exact six-case plan; does not allocate GPUs
uv run --no-project python -m experiments.relative_bias.benchmark
```

Torch/Triton-dependent tests skip when those packages are unavailable. These CPU checks do not revalidate CUDA execution.

The benchmark driver retains the original native-runtime contract. GPU execution requires two B300s, access to the pinned Inkling checkpoint, and the original compatible vLLM/CUDA environment; a generic PyPI vLLM installation is not equivalent. Model revision, image digest and native source hashes are in `experiments/context_sweep/runtime.py`. The provider-specific deployment and private runtime archive are not bundled. Within a prepared matching runtime, the driver accepts `--run --output-dir runs/<name>`; profiling runs must be separate from ordinary timing runs. Compatible cases retain one loaded engine, and the driver restores the helper and shuts down the engine on exit.

`SOURCE_MANIFEST.json` records source hashes from the extraction. Packaging edits remove unrelated framing only; benchmark parameters and observed values are retained. `ARTIFACT_MANIFEST.json` records the published files' hashes.
